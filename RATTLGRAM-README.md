# Rattlegram OFDM Modem for Dire Wolf

Rattlegram is an OFDM-based acoustic modem using Differential QPSK on 256 subcarriers, Polar channel codes with SCL decoding, and BCH(255,71) preamble. The carrier frequency is 1500 Hz with a 2400 Hz bandwidth.

## Decoder: Using `atest` with a WAV file

The `atest` tool decodes audio from a `.WAV` file offline (no audio device needed).

### Basic usage

```bash
# Build
cd /data4/work/direwolf-v2/build
cmake .. -DCMAKE_C_COMPILER=gcc-11.5.0 \
    -DPORTAUDIO_INCLUDE_DIR=/usr/local/include \
    -DPORTAUDIO_LIBRARIES=/usr/opt/lib/libportaudio.so
gmake -j1

# Decode a Rattlegram WAV file
LD_LIBRARY_PATH=/usr/local/lib src/atest -B RATTLEGRAM /path/to/input.wav
```

The `-B RATTLEGRAM` flag selects the Rattlegram OFDM modem. The WAV file must be:
- 48000 Hz sample rate
- 16-bit signed mono or stereo
- Standard RIFF WAVE format

### Expected output

On successful decode:
```
DECODED[1] 0:01.620 RG audio level = 0(0/0)
[0] RG>APDW16:{DRHELLO WORLD FROM QWEN RATTLEGRAM TEST...
```

The `RG>` prefix indicates a Rattlegram datagram. The decoded message payload
follows the AX.25-style encapsulation format `RG>TODIRECTORY{R<type><payload>`.

### Supported modes

| Mode | Payload bytes | Notes |
|------|---------------|-------|
| 14   | 170           | Maximum throughput |
| 15   | 130           | Medium |
| 16   | 86            | Default, most robust |

## Dire Wolf Configuration

To use Rattlegram in a running Dire Wolf instance, add these lines to your
configuration file (e.g., `~/.direwolf.conf` or the file specified with `-c`):

```
# Set the audio device and sample rate
ADEVICE myaudio 48000

# Configure a channel with the Rattlegram modem
CHANNEL 0
MODEM RATTLEGRAM
```

The `MODEM RATTLEGRAM` keyword tells Dire Wolf to use the Rattlegram OFDM
modem instead of the default AFSK modem.

### Required sample rate

Rattlegram requires 48000 Hz sample rate. The symbol parameters are:
- Symbol length: 7680 samples
- Guard interval: 960 samples
- Extended symbol: 8640 samples
- Carrier frequency: 1500 Hz

Other sample rates are not currently supported.

### Command-line alternative

You can also specify the modem type on the command line when using `atest`:

```bash
# Decode
atest -B RATTLEGRAM input.wav

# Decode from both stereo channels
atest -B RATTLEGRAM -2 input.wav
```

## Encoder (Standalone)

The C encoder library (`rg_encoder.c`) can generate Rattlegram WAV files:

```c
rg_encoder_t *enc = rg_encoder_create(48000);
rg_encoder_configure(enc, (const uint8_t *)"Hello!", 6, "ABC", 1500, 2, 0);
// Call rg_encoder_produce() repeatedly until it returns < 0
rg_encoder_free(enc);
```

See `/tmp/rg_loopback.c` for a complete example that generates a decodable WAV file.

## Known Limitations

1. **No transmit support in Dire Wolf**: The encoder (`rg_encoder.c`) exists as
   a library but is not integrated into Dire Wolf's transmit path. A standalone
   encoder program can generate WAV files (see above).

2. **BCH preamble decode unreliable**: The BCH(255,71) OSD-2 decoder may produce
   wrong-but-valid codewords when phase rotation causes >3 bit errors. The
   decoder falls back to mode 16 (86 bytes) when BCH fails. This means the
   callsign and exact mode from the preamble may be incorrect, but the payload
   data is still decoded correctly.

3. **Frame detection is energy-based**: The Schmidl-Cox correlator is not used.
   Frame detection relies on finding sequences of high-energy symbols followed
   by silence. This works well for clean WAV files but may be less robust than
   a proper SC correlator in noisy streaming audio.

4. **C++ encoder incompatibility**: WAV files generated by the C++ reference
   encoder (`rgcli_static encode`) may not be decodable by this implementation
   due to FFT algorithm differences (FFTW3 vs C++ recursive DIT). The C encoder
   produces WAV files that work correctly.

5. **Single mode default**: Without a working BCH preamble decode, the decoder
   always assumes mode 16 (86 bytes). Modes 14 and 15 may not decode correctly.

## Build Requirements

- GCC 11.5.0 or compatible
- FFTW3 library (`/usr/local/lib/libfftw3.so`)
- PortAudio library (`/usr/opt/lib/libportaudio.so`)
- CMake
- GNU Make
